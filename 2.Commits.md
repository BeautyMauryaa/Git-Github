# 2.1 What exactly is a commit?

* `git add` → puts changes into the staging area
* `git commit` → records those changes in Git history

# 2.2 Commit Snapshot

* A commit is a snapshot of the project at a specific point in time.
* Git does not store a completely separate copy of the project for every commit.

# 2.3 Commit Hash

* Every commit gets a unique identifier.
* Ex: `a83f91c7d4...` → this is a commit hash.
* We can see it with `git log --oneline`.

# 2.4 Parent Commits

* Every commit points to its previous commit.
* This previous commit is called the **parent commit**.

# 2.5 HEAD

* `HEAD` points to the commit we are currently working from.
* Usually, `HEAD` points to the current branch.

# 2.6 Branch Pointer

* A branch is simply a pointer to a commit.
* When we make a new commit, the branch pointer moves to the new commit.

# 2.7 Reading Git History

* `git log` → shows the commit history.
* `git log --oneline` → shows a shorter version of the history.
* Each commit has a hash, message, and parent commit.

# 2.8 Good Commit Practices

* Write clear and meaningful commit messages.
* Keep commits small and focused.
* One commit should represent one logical change.

# 2.9 Practical Exercise

* Create a repository.
* Make some changes.
* Stage and commit the changes.
* Check the commit history using `git log --oneline`.
