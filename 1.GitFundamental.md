# 1.1 What is Git?

- **Git is a distributed version control system (VCS)** used to track and manage changes in a project.
- It maintains a **history of changes**, allowing us to:
  - Track changes made to files
  - Compare different versions
  - Go back to previous versions
  - Work on features separately using branches
  - Combine work from multiple developers
  - Identify when a bug or change was introduced
  - Collaborate safely without overwriting each other's work

---

# 1.2 Repository & `.git`

Assume we have a project called `pract`:

```text
pract/
├── index.html
├── style.css
├── app.js
└── .git/
```

- A **Git repository** is a project that Git is tracking.
- The `.git` directory is what makes a normal project folder a **Git repository**.
- `git init` creates the `.git` directory.

```bash
git init
```

### Remember:

```text
Actual Project + .git = Git Repository
```

- `.git/` contains Git's **internal information, metadata, and complete version history**.
- We normally don't modify anything inside `.git` manually.

---

# 1.3 Working Directory

The **working directory** is the actual project files that you are currently working on.

For example:

```text
index.html
style.css
app.js
```

If you modify `index.html`, that change currently exists in your **working directory**.

Think of it as:

> **"The files I'm currently editing."**

---

# 1.4 Staging Area

The **staging area** is where we prepare changes that we want to include in the **next commit**.

For example, suppose we modified three files:

```text
index.html
style.css
app.js
```

But we only want to commit the first two.

```bash
git add index.html
git add style.css
```

Now:

```text
index.html  → Staged
style.css   → Staged
app.js      → Not staged
```

So, the staging area allows us to **choose exactly which changes should go into the next commit**.

---

# 1.5 Local Repository

The basic Git workflow is:

```text
YOU EDIT
   ↓
Working Directory
   ↓
git add
   ↓
Staging Area
   ↓
git commit
   ↓
Local Repository / Git History
```

### Meaning:

- **Working Directory** → Changes you are currently making
- **Staging Area** → Changes selected for the next commit
- **Local Repository** → Commits/history stored by Git locally

---

# 1.6 Git File States

A file can generally move through these states:

```text
Untracked
   ↓
Modified
   ↓
Staged
   ↓
Committed
```

### 1. Untracked

Git is not tracking the file yet.

### 2. Modified

Git already knows about the file, but its contents have changed since the last commit.

### 3. Staged

The changes have been added to the staging area and are ready for the next commit.

### 4. Committed

The staged changes have been permanently recorded in Git history as a commit.

# 1.7 `git status`

```bash
git status
```

`git status` tells us **what is currently happening in our Git repository**.

It can show things such as:

- Untracked files
- Modified files
- Staged files
- Current branch
- Other useful repository information

### Remember:

> When you're confused about what's happening in Git, **check `git status` first.**

---

# 1.8 `git add`

`git add` moves the current version of a file's changes into the **staging area**.

### Add a specific file:

```bash
git add index.html
```

### Add multiple files:

```bash
git add index.html style.css
```

### Add everything:

```bash
git add .
```

### Meaning:

> **"Stage the current changes for the next commit."**

Important: `git add` **does not create a commit**. It only stages the changes.

---

# 1.9 `git commit`

A commit records the changes that are currently in the **staging area**.

Example:

```bash
git commit -m "Add button"
```

Here:

- `git commit` → Creates a commit
- `-m` → Allows us to provide a commit message
- `"Add button"` → Describes what the commit contains

### Basic flow:

```text
Working Directory
       ↓
    git add
       ↓
 Staging Area
       ↓
  git commit
       ↓
 Git History
```

### Important:

A commit contains **only the changes that were staged**.

---

# 1.10 `git log` / `git show`

## `git log`

Used to view the **commit history**.

```bash
git log
```

For a cleaner, shorter output:

```bash
git log --oneline
```

Example:

```text
a81f23d Add login page
72bc91a Fix navbar
19da832 Initial commit
```

---

## `git show`

Used when you want to inspect a **specific commit** and see what that commit changed.

```bash
git show <commit-hash>
```

Example:

```bash
git show a81f23d
```

It shows information about the commit along with the changes introduced by that commit.

---

# 1.11 `git diff`

`git diff` shows the difference between your **last committed version** and your **current unstaged changes**.

Example:

```bash
git diff
```

If you modify `index.html` but haven't run `git add` yet:

```text
Last Commit
     ↓
   changes
     ↓
Working Directory
```

`git diff` shows those changes.

### Important distinction:

```bash
git diff
```

→ Shows **unstaged changes**

```bash
git diff --staged
```

→ Shows **staged changes** that are ready to be committed.
